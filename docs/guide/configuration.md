# Configuration

The defaults work without a published config. To customize them, run `php artisan vendor:publish --tag=rehearsal-config` in the Laravel root. Edit the resulting `config/rehearsal.php`, preserving the built-in entries you still need. Laravel merges this file with the package config at the top level, not recursively.

## Environment and bridge

| Key | Default | How to use it |
| --- | --- | --- |
| `enabled` | `REHEARSAL_ENABLED` or `false` | The managed launcher enables the bridge; leave it off in normal app environments. |
| `environments` | `REHEARSAL_ENVIRONMENTS` or `testing,rehearsal` | An array of allowed Laravel environments. The env value is a comma-separated list. |
| `run` | `REHEARSAL_RUN` or unset | Managed run ID; generated by the launcher, not a project setting to commit. |
| `capability` | `REHEARSAL_CAPABILITY` or unset | Managed control credential; generated by the launcher, never put it in app or browser config. |
| `safe_defaults` | `[]` | Overrides the safety values below. Use `null` to retain Laravel's existing value for a key. |
| `route_mocks` | `true` | Enables browser/SSR route responses and gates. Does not control server faults. |
| `fault_paths` | `['discover' => true]` | Accepts application paths by default, excluding control endpoints. Use `false` to disable or an exact path list such as `['/api/feed']` to restrict. |
| `login` | `true` | Enables the login helper. Use `['guard' => 'web']` to select a guard, or `false` to disable. With no explicit guard, the helper uses the default stateful guard or falls back to `web` when configured. |

With an active run, Rehearsal starts with `session.driver=array`, `cache.default=array`, `queue.default=null` (the null driver), `mail.default=log`, `broadcasting.default=log`, `scout.driver=null` (the null driver), and `app.debug=false`. Integrations can still replace these as they bind an attempt. For example, Laravel State binds sessions, cache, queues, and rate-limit counters to the attempt database, including when an app registers named limiters at boot. An explicit `cache.limiter` store is not replaced; isolate it separately if needed.

```php
'safe_defaults' => ['app.debug' => true, 'mail.default' => null],
'login' => ['guard' => 'web'],
'fault_paths' => ['/api/feed'],
```

Only opt out of a safe default or built-in integration when the replacement uses disposable, isolated state.

## Database and storage

| Key | Default | How to use it |
| --- | --- | --- |
| `database.driver` | `REHEARSAL_DB_DRIVER`, then `DB_CONNECTION`, then `sqlite` | `sqlite`, `mysql`, or `pgsql`. Use the same engine as production when the behavior under test depends on its SQL semantics. |
| `database.sqlite_transaction_mode` | `REHEARSAL_SQLITE_TRANSACTION_MODE` or `DEFERRED` | `DEFERRED`, `IMMEDIATE`, or `EXCLUSIVE`. Set a non-default mode with PHP 8.4+; `IMMEDIATE` can help with competing read-then-write transactions within one attempt. |
| `database.disposable_server` | `REHEARSAL_DB_DISPOSABLE` or `false` | Must be true for a disposable loopback MySQL or PostgreSQL server. |
| `database.aliases` | `[]` | Additional Laravel connection names to point to the isolated database, e.g. `['reporting']`. This is not a way to create multiple isolated databases. |
| `database.seeder` | `REHEARSAL_DB_SEEDER` or unset | Seeder class to run against the migrated baseline, e.g. `Database\Seeders\BrowserTestSeeder::class`. |
| `disks` | `['local', 'public']` | Filesystem disk names isolated by the Filesystem integration. Use their generated URLs. |
| `queues` | Not explicitly set | A non-empty list such as `['default', 'reports']` overrides the inferred queue allowlist (database queue name plus configured Horizon queues, falling back to `default`). |

See [service integrations](./services#mysql-or-postgresql) for database setup outside SQLite.

## Registries and discovery

| Key | Default | How to use it |
| --- | --- | --- |
| `integrations` | Discovery on; `database`, `filesystem`, `laravel-state`, `clock` | Map keys to implementation classes or use `false` for a key to disable it. Keep the ordering of integrations with dependencies. |
| `factories` | `['discover' => true]` | Set scan paths, state discovery, and per-alias overrides. |
| `operations` | `['discover' => true]` | Set scan paths and add, replace, or disable named operations. |
| `artisan` | `['discover' => true]` | Allow registered Artisan commands, override selected names with validated aliases, or set discovery off for an explicit allowlist. |
| `schedule` | `['discover' => true]` | Discover scheduled Artisan tasks; add aliases or disable an entry with `false`. |
| `callbacks` | `['discover' => true]` | Set scan paths; map exact callback paths to a verifier class or `false`. |

The [auto-discovery reference](../concepts/discovery) explains scan paths and precedence. See the [override examples](./extending) for definitions you can adapt.

## Optional services

| Key | Default | How to use it |
| --- | --- | --- |
| `mailpit.api` | `REHEARSAL_MAILPIT_API`, then `MAILPIT_URL`, otherwise unset | Loopback Mailpit API origin, e.g. `http://127.0.0.1:8025`. |
| `mailpit.smtp_port` | `REHEARSAL_MAILPIT_SMTP_PORT`, then `MAIL_PORT`, then `1025` | Integer SMTP port on the Mailpit host. |
| `scout.engine` | `REHEARSAL_SCOUT_ENGINE`, then `SCOUT_DRIVER`, otherwise unset | `database`, `meilisearch`, or `typesense`. Install Scout and any required engine client. |
| `scout.origin` | `REHEARSAL_SCOUT_ORIGIN` or unset | Loopback search server origin for remote engines. Not needed with the database engine. |
| `scout.admin_key` | `REHEARSAL_SCOUT_ADMIN_KEY` or unset | Disposable remote engine administrator key. Put it only in the local env or CI secret store. |
| `scout.models` | `['discover' => true]` | Searchable model list. Use explicit order for Typesense reference fields. See [model discovery](../concepts/discovery). |
| `scout.baseline_models` | `REHEARSAL_SCOUT_BASELINE_MODELS` (comma-separated) or `[]` | Typesense-only list of model class names to reimport from the restored database on every attempt. |
| `reverb.origin` | `REHEARSAL_REVERB_ORIGIN`, otherwise `http://${REVERB_HOST}:${REVERB_PORT}` when a host is set (port defaults to `8080`), otherwise unset | Loopback origin for a disposable Reverb daemon. |
| `reverb.server` | `REHEARSAL_REVERB_SERVER` or `false` | Set true in the standalone test Reverb console process, not in the ordinary app server. |

See [working service configurations](./services#mailpit-scout-and-reverb) and the [Playwright launcher options](../reference/typescript#laravelserver).
